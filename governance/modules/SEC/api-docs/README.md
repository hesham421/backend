# SEC — api-docs (not yet generated)

This directory is the `api_docs_path` that `governance/modules/SEC/execution-state.json`
points at, and the location `governance/governance-tools/api-doc-generator/` writes to
(`discovery.default_output_dir()` → `governance/modules/<MODULE>/api-docs/`).

**It is empty on purpose. Nothing here is hand-written, and nothing here imitates
generator output.**

## What belongs here

The generator's own layout, and nothing else:

```
api-docs/
├── index.md                 module overview, auth, common headers, shared
│                            ApiResponse<T>/Page<T> envelopes, known error codes,
│                            API catalog
└── endpoints/
    └── <group-slug>.md      one file per @Tag group (= controller), each endpoint
                             a "## {METHOD} {path}" section
```

Every generated file carries the marker line
`<!-- AUTO-GENERATED by api-doc-generator — do not edit manually -->`.

Note that the generator produces `index.md` + `endpoints/*.md`; it does **not** produce a
single `api-docs-sec.md`. The DOC phase text in
`packages/backend-execution/DOC/DOC.md` and `P3_1/backend-execution-plan-sec.md` still
refers to "the real `api-docs-sec.md` published after implementation" — that filename has
no producer. Which name is authoritative is an open question for a human; it was not
silently changed here.

## Why it has not been generated

The generator extracts exclusively from a **live** OpenAPI document served by the running
backend — `openapi_extractor.py` loads JSON from a URL or a saved file, and
`discovery.resolve()` builds that URL as
`http://localhost:<port>/api-docs/<springdoc-group-id>`. Two things block that here:

1. **No `GroupedOpenApi` bean exists anywhere in `src/main/java/`.** Discovery identifies a
   module by matching `--module` against a springdoc group's method name / group id /
   display name / scanned packages. With no such bean the resolution fails outright:

   ```
   ERROR: Could not identify a unique springdoc GroupedOpenApi group for module 'SEC'
   under '/Users/ezzat/my project/backend'. Pass --openapi explicitly (a live URL or a
   saved JSON file).
   ```

   Adding that bean means adding a class under `src/main/java/`, which the DOC phase is
   explicitly scoped not to do.
2. **This repo exposes one ungrouped document.** `application.properties` sets
   `springdoc.api-docs.path=/v3/api-docs` and declares no groups, so the only document
   available covers SEC **and** CU, NOTIF and FILE together. Pointing `--openapi` at it
   would publish every module's endpoints under `modules/SEC/api-docs/` — wrong content in
   the right folder, which is worse than an empty folder.

No module in this repository has an `api-docs/` directory (checked: CU, FILE, FIN, MDL,
NOTIF, SEC), so there is no established published-output pattern to mirror either.

## The exact command that would produce it

Once a per-module `GroupedOpenApi` bean exists and the app is running:

```bash
cd governance/governance-tools/api-doc-generator
python3 generate.py --module SEC --function generate   # first publish
python3 generate.py --module SEC --function update     # re-publish after a backend change
python3 generate.py --module SEC --function review     # report drift, write nothing
```

Until then the authoritative backend-side contract summary is the API table in
`governance/modules/SEC/packages/backend-execution/DOC/DOC.md`, which is a self-check
table — not a substitute for generated documentation, and explicitly not what the
frontend stage binds to.
