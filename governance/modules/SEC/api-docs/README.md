# SEC — api-docs (generated)

This directory is the `api_docs_path` that `governance/modules/SEC/execution-state.json`
points at, and the generator's own default output location
(`governance/governance-tools/api-doc-generator/discovery.py` → `default_output_dir()` →
`governance/modules/<MODULE>/api-docs/`).

Everything here except this README is produced by that tool and carries the marker line
`<!-- AUTO-GENERATED by api-doc-generator — do not edit manually -->` as its first line.
Nothing here is hand-written.

## Layout

```
api-docs/
├── index.md                 module overview, servers, shared ApiResponse<T>/Page<T>
│                            envelopes, common headers, error codes, API catalog
└── endpoints/
    └── <group-slug>.md      one file per @Tag group (= controller), each endpoint
                             a "## {METHOD} {path}" section
```

## Naming — settled

The generator produces `index.md` + `endpoints/<group-slug>.md`; no configuration of it
produces a single `api-docs-sec.md`, and `api_docs_path` names a *directory*, not a file.
The generator's layout is therefore authoritative and `api-docs-sec.md` has been struck
from the plan: the DOC-phase "API contract summary" paragraph in
`governance/modules/SEC/P3_1/backend-execution-plan-sec.md` (line 1115) and its
byte-identical twin in `packages/backend-execution/DOC/DOC.md` (line 6) now bind the
frontend stage to "the real generated api-docs published under
`governance/modules/SEC/api-docs/` … `index.md` plus `endpoints/<group-slug>.md`".

## Regenerating

Requires the backend running (`server.port=7272`, dev profile) and the per-module
`GroupedOpenApi` beans in `src/main/java/com/erp/main/config/OpenApiConfig.java`, which
are what `discovery.match_openapi_group` matches `--module SEC` against.

```bash
cd governance/governance-tools/api-doc-generator
# first publish / full rewrite
python3 generate.py --module SEC --function generate --openapi http://localhost:7272/v3/api-docs/sec
# re-publish after a backend change (writes only what differs)
python3 generate.py --module SEC --function update   --openapi http://localhost:7272/v3/api-docs/sec
# report drift, write nothing
python3 generate.py --module SEC --function review   --openapi http://localhost:7272/v3/api-docs/sec
```

`--openapi` is **required**, not optional, because of two defaults in `discovery.py` that
are wrong for this repository. It is the tool's own sanctioned escape hatch (`resolve()`
accepts `openapi_override`; `generate.py`'s help calls it an explicit override for "server
not running on the expected port"), so it is used here rather than editing shared tooling:

1. `resolve()` builds the URL as `http://localhost:<port>/api-docs/<group-id>`, missing the
   `/v3` prefix — `application.properties` sets `springdoc.api-docs.path=/v3/api-docs`, so
   the live document is at `/v3/api-docs/sec`.
2. `find_server_port()` discovers the port by scanning Java source for
   `@Value("${server.port:<n>}")`. No such annotation exists here — the port is declared in
   `application.properties` (`server.port=7272`) — so it falls back to `8080`.

Passing `--openapi` alone is enough: discovery still matches the `sec` group from
`OpenApiConfig` and derives `--source` (`src/main/java/com/erp/sec`) and the common source
root from it, so the permission, error-code and common-header sections are still populated.
