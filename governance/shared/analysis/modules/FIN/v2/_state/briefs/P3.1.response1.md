**What v2 adds**
- **Account mappings:** four endpoints, API-FIN-038 to 041 (search, create, change account, deactivate), with the new FIN_ACCOUNT_MAPPINGS screen and its three permissions.
- **Changed endpoints:** API-FIN-011 (adding a rule line) now takes the mapping business field and dimension tags. API-FIN-020 (building an entry from an event) now takes accounts from mappings, reads dimensions from the event, and gives each rejection its own error.
- **Duplicate events:** answered as `FIN-409-DUPLICATE-EVENT` in both cases, including when two copies arrive at once and the database refuses the second. A module-wide translator handles that database refusal (ADR-FIN-030).
- **Closed period:** the event consumer gets a table of which errors to acknowledge, which to retry (`FIN-409-PERIOD-NOT-OPEN`), and which need a fix.
- **Other additions:** 12 new error codes, 12 new queries (QR-FIN-050 to 061), a bootstrap section (15 lookup keys and 30 permissions, each saying who seeds or grants it), and entity blocks for ENT-FIN-015 and 016.

**Decision you may want to review:** the delta re-emits the whole plan, not just what changed (ADR-FIN-029). `gov.py state` only carries a phase's direct children, so re-emitting a sub-group with only its new endpoints would have silently dropped every v1 endpoint in it. Separately, the v1 plan fails today's checks (77 MAJOR findings when I ran them). So every v1 endpoint and entity block got annotation-only changes: an `Entity` line, the columns it writes, a `Concurrency` line, and the sequence name instead of `GENERATED ALWAYS AS IDENTITY`. No behaviour changed. The downside: the manifest lists every v1 block as MODIFIED, so any later stage that re-runs by changed id will revisit all of them.
